# Accuracy audit of v1 (2026-09-21): where every finding lands

*Unofficial — not affiliated with Robinhood Markets, Inc.*

On 2026-09-21 the v1 skill (`robinhood-trading/`, commit 25d7e4d) was audited line by line against the 81 live tool schemas (`connector/schemas/`). The audit found **121 discrepancies: 9 critical, 73 major and 39 minor**. This file is the checklist for fixing all of them in v2.0.0. Each finding has one checkbox and the files it lands in, with the work package (WP) that owns each file.

**IDs.** Findings are numbered in audit order within each severity, family by family (accounts, market data, research, equity and OCO orders, options and crypto orders, scanner, watchlists and alerts): C1–C9 critical, M1–M73 major, N1–N39 minor (N, so a minor ID never reads like a major one). The connector rules cite them as `[ACC C1]`, `[ACC M31]`.

**Destination keys** (the "Lands in" line; C and M rows are copied verbatim from build spec §C.4):

| Key | Means |
|---|---|
| S-Rn | `shared/connector-rules.md` rule n, synced into every skill |
| INV n | item n of `shared/invariants.md`, the block synced into every SKILL.md |
| core/X, core A–K | `skills/robinhood-trading/references/X`, or workflow A–K of its SKILL.md |
| tax, grd, mon, rc, scr | the tax-loss-harvesting, exit-guardian, options-monitor, report-card and options-screener skills |
| hook, CI | `hooks/` (guard and matchers); `tools/check_drift.py` |
| case Xn | the eval case template `evalkit/templates/Xn/` |
| **X** | the v1 text is deleted (it was wrong, or its subject no longer exists) |

**Ticking.** A finding's box is ticked when every file on its line is done. The WP that finishes the last open file ticks it. At generation (2026-09-22, WP-B): **15 ticked** (every destination is a WP-B file, now written, or the WP0 capture), **56 partly done** (the WP-B part is written; other owners remain), **50 open**.

**Integration check (2026-09-22, WP-Z): all 121 ticked.** After every work package landed, each open finding was checked against the integrated tree: every destination file exists, and the specific rule, parameter, script code, eval case or README row that the finding asks for is present (the v1 files marked **X** are gone). One gap was fixed during integration: N24 (the screener now says why its option review is always a limit order). The tests, `tools/check_drift.py` and the generated eval graders keep the machine-checkable parts of these fixes from regressing.
